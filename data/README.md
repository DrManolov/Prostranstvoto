# Частни исторически източници

Публичният GitHub съдържа програмния код и `source-manifest.json` с имена и SHA-256 контролни суми. Самите DOCX, извлеченият текст, финансовият анализ, генерираните документи и базата данни остават частни. Всички те се запазват в подготвената работна среда; изтеглянето на публичния код не прехвърля тези данни.

Без оригиналите приложението стартира с празни регистри. За исторически импорт и генериране по университетския шаблон са необходими Вашите действителни 14 документа. Не се създава заместител на Word шаблона.

## Добавяне на оригиналите

1. Сложете предоставените 14 DOCX в папка на компютъра си. Двата файла с еднакво име за юни и юли могат да имат различни имена или да са в подпапки.
2. Отворете терминал в папката на приложението и изпълнете с Python 3:

   ```bash
   python scripts/prepare_sources.py "път-до-папката-с-документите"
   ```

   Програмата разпознава точните оригинали по SHA-256, така че имената и редът им не са определящи. Копира ги без промяна в игнорираната от Git папка `data/originals` с необходимите за импорта префикси. Съществуващ различен файл не се презаписва.

   На Windows, ако имате само Docker Desktop, поставете документите в подпапка `data/originals/incoming` на приложението и изпълнете от неговата папка:

   ```powershell
   docker run --rm --mount "type=bind,source=$($PWD.Path),target=/app" -w /app python:3.12-slim-bookworm python scripts/prepare_sources.py data/originals/incoming
   ```

3. Изградете отново приложението, за да включите частните оригинали в собствения си локален образ:

   ```bash
   docker compose up -d --build --wait --wait-timeout 180
   ```

   При стартиране историческият импорт се изпълнява автоматично и идемпотентно. Той не създава участници или банкови операции от обобщените стари такси. Анализът е в `runtime/historical-analysis.md`, а несъответствията се виждат след вход.

## Шаблонът за юли

`01_Месец 6 2026 -  ПФ+.docx` е юлският шаблон според съдържанието; `14_Месец 6 2026 -  ПФ+.docx` е реалният юнски отчет. Не ги разменяйте по име. Програмата за подготовка ги различава по контролните суми.

## Частно съхранение

Пазете `.env`, `runtime`, `data/originals`, `data/extracted`, частния анализ и генерираните файлове извън публичен Git. Не публикувайте Docker образ, който включва оригиналите. За преместване между собствени сървъри използвайте защитен архив и процедурите в `docs/DEPLOYMENT.md`. За включване на оригиналите в Git първо е необходимо отделно частно хранилище и решение на администратора.
