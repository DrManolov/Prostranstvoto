# Пространството ПФ+

Работеща първа версия на вътрешна система за курсове, финанси и административни документи на Педагогическия факултет на ПУ „Паисий Хилендарски“. Интерфейсът е на български, основната валута е EUR.

Използвани са Django 5.2 LTS, PostgreSQL 17, `Decimal`, оригиналният OOXML/Word пакет и LibreOffice Writer. Django осигурява поддържани механизми за автентикация, сесии, CSRF, миграции и административни настройки; финансовата логика е в отделен сървърен модул.

## Стартиране

**Изтегляне:** [Code → Download ZIP](https://github.com/DrManolov/Prostranstvoto/archive/refs/heads/main.zip). Разархивирайте файла на компютъра си.

**Windows:** инсталирайте и стартирайте Docker Desktop, после отворете с двойно щракване **`START-WINDOWS.cmd`** от разархивираната папка. При първото стартиране изчакайте изграждането на приложението и въведете име и собствена парола за администратора в отворения прозорец. Скриптът ще отвори браузъра. При следващо стартиране използвайте същия файл и съществуващия профил. Не е необходима отделна инсталация на Python за този начин.

GitHub съдържа програмния код. **Оригиналните финансови DOCX, извлечените данни, анализът и генерираните документи не се публикуват в публичното хранилище.** Без тях приложението стартира с празни регистри. За историческите отчети и оригиналния Word шаблон следвайте [добавяне на частните източници](data/README.md).

За ръчно стартиране са необходими Python 3.12, Docker Engine и Docker Compose v2. Отворете терминал в разархивираната папка. Използвайте съществуващото хранилище; не е необходим Git worktree.

```bash
python scripts/init_local.py
docker compose up -d --build --wait --wait-timeout 180
docker compose exec web python manage.py ensure_admin
```

Последната команда създава Вашия администраторски профил и пита за парола в терминала. Няма обща фабрична парола. При локално стартиране приложението слуша на порт 8000 на Вашата машина. В облачната среда за тази задача не се предоставя публичен уеб преглед.

В тази облачна машина образът вече е изграден и PostgreSQL е подготвен. За повторно стартиране с предоставения мрежов proxy:

```bash
python scripts/cloud.py up
```

При промени по кода: `python scripts/cloud.py build`, след това `python scripts/cloud.py up`. В обикновена локална среда използвайте `docker compose up -d --build`. Не изключвайте TLS или проверките на пакетите.

Началното стартиране изпълнява миграциите, идемпотентния исторически импорт, създаването на роли и събирането на статичните файлове. PostgreSQL данните са в защитената, игнорирана от Git директория `runtime/pgdata`; частните файлове са в `runtime/private`. `.env` се създава с произволни локални ключове и права 0600 и не се включва в Git или Docker образа.

## Реализирано

- Защитен вход, смяна на парола, ограничаване на опитите за вход, роли администратор / счетоводител / само преглед и история на промените.
- Курсове, лектори, ценови категории, участници, планови бюджети и праг на покриване на разходите.
- Самостоятелни приходи, частични плащания, закъснели плащания, продажби на записи, свързани възстановявания и прикачени платежни документи. Получаването се потвърждава отделно.
- Обща уникалност на платежните референции между приходи, плащания по разходи и преводи. Потвърдените приходи не се редактират.
- Разходи в състояния предвиден / одобрен / дължим; реалните плащания по тях и реалните преводи се въвеждат отделно.
- Финансови правила, осигурителни ставки и длъжностни лица с периоди на валидност и изискване за счетоводно потвърждение. Първоначалните предложения са **непотвърдени**.
- Финансово табло, месечна графика, филтри, аналитика по курсове, Excel/CSV експорт на регистрите.
- Приключване, утвърждаване с основание, заключване и обосновани ревизии със запазен предходен snapshot. Остатъкът на новите отчети идва от предходния утвърден отчет.
- Импорт на 14-те частни оригинални DOCX: 14 исторически отчета и 225 първоначални финансови реда. Отделен регистър на несъответствията и исторически корекции по редове, които не презаписват оригиналите. Самите файлове се добавят отделно.
- Общи и отделни DOCX/PDF проекти, преглед в приложението и проследимост на данните и контролните суми. Ненужни заповеди не се създават.
- Реален Google OAuth2 / Forms API код за създаване, публикуване и синхронизация. Външната интеграция изисква Ваш OAuth клиент, разрешение и уведомление за личните данни; не се симулира.
- Архивиране и възстановяване на PostgreSQL и частните файлове.

## Първи стъпки след вход

1. След добавяне на частните източници прегледайте „Открити несъответствия“ и генерирания файл `runtime/historical-analysis.md`. Оригиналните стойности не са поправяни автоматично.
2. В „Правила и настройки“ потвърдете приложимите правила, ставки и длъжностни лица **само след реално потвърждение от счетоводството**. Задайте реалните им периоди на действие.
3. Създайте курс и ценови категории. Добавете участници ръчно или [свържете Google](docs/GOOGLE.md).
4. Въведете постъпление и потвърдете действителното получаване. Одобрете разходите и въведете реалното им плащане отделно.
5. Създайте отчетен период, прегледайте изчисленията и генерирайте документи. Отбелязвайте утвърждаване само когато действително е извършено.

Подробности: [ръководство за работа](docs/USER_GUIDE.md), [внедряване и архиви](docs/DEPLOYMENT.md), [Google Forms](docs/GOOGLE.md), [валидация](docs/VALIDATION.md).

## Разработка и тестове

Python 3.12 и локална виртуална среда; PostgreSQL остава в Docker:

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
docker compose up -d db
.venv/bin/python manage.py migrate
.venv/bin/python manage.py import_history
.venv/bin/python manage.py init_roles
.venv/bin/python manage.py collectstatic --noinput
.venv/bin/python manage.py test ledger.tests.FinanceTests ledger.tests.GoogleTests --noinput
```

Пълният набор, включително приемателните проверки срещу реалните документи, се изпълнява след добавяне на всички 14 частни DOCX: `python manage.py test ledger --noinput`. Историческите тестове изискват оригиналите; те не са заменени с измислени публични данни.

За Python разработка извън web контейнера PDF конверторът може да се използва от изградения образ:

```bash
SOFFICE="$PWD/scripts/soffice-docker.py" .venv/bin/python manage.py runserver --nostatic
```

Наличен е и реален тест през браузър в **отделна временна PostgreSQL база**:

```bash
.venv/bin/python scripts/smoke_test.py
```

Той изисква Node.js, Playwright и Chromium (може да се зададе `CHROMIUM_PATH`). Не добавя тестови финансови записи в основната база. Обичайните финансови тестове не изискват браузър.

## Граници на първата версия

Историческите документи не доказват конкретни участници, банкови операции, точни часове или еднозначно разпределение на всеки общ разход по курс/лектор. Тези данни не са измисляни. Точните дати, лектори и текущи регистрационни цени се допълват от администратора, когато източникът не е еднозначен. Филтърът по лектор показва приходи на свързаните курсове; не означава личен дял на лектора и не трябва да се сумира повторно за съвместно водени курсове.

Историческото табло пази първоначално импортираната база, конвертирана по фиксирания курс. Обоснованите корекции се виждат в отчетните ревизии и новите документални проекти. При ръчна корекция на свързани редове администраторът трябва да провери и съответните сборове и получатели; системата не преправя останалите исторически числа автоматично.

Импортът на банкови извлечения, автоматичното банково съпоставяне, електронното подписване и автоматизирано счетоводно осчетоводяване не са включени. Генерираният PDF не е електронно подписан. Публично внедряване и реален Google OAuth цикъл не са извършвани без Ваши данни и разрешения. Приложението не замества университетската счетоводна система.
